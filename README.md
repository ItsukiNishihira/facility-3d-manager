# facility-3d-manager
業務改善アプリ

Facility 3D Manager（修繕3D）：全店舗の設備修繕を、写真付きで3Dモデル上に記録・共有し、本社で一括管理して修繕遅れをなくすためのアプリです（要件定義書「Facility 3D Manager 要件定義書」に基づく）。

- スマホ・PCで開く：https://itsukinishihira.github.io/facility-3d-manager/ （`main` ブランチの内容がそのまま公開されます）
- ホーム画面に追加すると、アプリのように起動できます（PWA）

## 業務の流れ

1. **報告（店舗スタッフ）**：3Dモデルの部屋・共用部をタップし、場所（エアコン・浴室など）と写真を登録。写真の登録日＝修繕依頼日
2. **確認と予定（本社管理者）**：案件を開き、対応予定日をカレンダーから選んで担当者（店舗スタッフ）を設定
3. **修理（担当者）**
4. **完了報告（店舗スタッフ）**：修理後の写真と費用を登録。写真の登録日＝対応完了日

日付はデータベース側で自動記録され、手入力はできません。

## ステータス色

対応予定日からの経過日数（日本時間、予定日の当日＝0日目）で自動的に切り替わります。1つの場所に複数の案件があるときは「赤 → 黄 → 青 → グレー → 緑」の順で優先して表示します。

| 色 | 条件 |
|---|---|
| 黄 | 報告済みで、対応予定日が未設定 |
| グレー | 予定日の前日まで、または予定日から0〜2日 |
| 青 | 予定日から3〜6日、未完了 |
| 赤 | 予定日から7日以上、未完了（修繕遅れ） |
| 緑 | 完了（3Dモデルとダッシュボードでは完了から30日以内のものを表示） |

## 画面

| 画面 | 内容 | 利用者 |
|---|---|---|
| 3Dモデル | 店舗ごとの建物。部屋・共用部の色と目印で状態を表示。報告・完了報告・室内3D | 全員 |
| ダッシュボード | 店舗ごとの色別件数。遅れている店舗が上に来る | 本社管理者 |
| 修繕一覧 | 店舗・色・担当者・期間で絞り込み、並び替え | 全員（見られる店舗のみ） |
| カレンダー | 対応予定日の月表示・週表示、担当者・店舗で絞り込み | 本社管理者 |
| 管理 | スタッフの役割・有効化・閲覧できる店舗、店舗の追加・建物の形・LINEグループID | 本社管理者 |

## 構成

- `index.html`：画面とスタイル
- `js/app.js`：ログイン・データの読み書き・各画面
- `js/building.js`：3Dモデル（three.js）。建物の形は店舗ごとのデータ（`stores.building`）から生成するので、店舗追加時にアプリを作り直す必要はありません
- `sw.js`・`manifest.webmanifest`・`icons/`：PWA
- `supabase/migrations/`：データベース構成（Supabase プロジェクト `facility-3d-manager`）。店舗ごとの閲覧範囲は RLS でデータベース側でも制限しています
- `supabase/functions/line-notify/`：修繕依頼・完了時に店舗のLINEグループへ通知する Edge Function

## セットアップ

1. `supabase/migrations/` の SQL をファイル名の順に実行する
2. Supabase 管理画面の Authentication → Users → Add user でアカウントを作成する（LINEログイン導入までの暫定）
3. 最初の本社管理者だけは SQL Editor で有効化する
   ```sql
   update public.profiles set role = 'admin', active = true where email = '管理者のメールアドレス';
   ```
4. 以降のスタッフは、アカウント作成後にアプリの「管理」画面で役割・閲覧できる店舗を設定して有効にする

### LINE通知を使う場合

1. Edge Function `line-notify` をデプロイする（`supabase functions deploy line-notify`）
2. シークレット `LINE_CHANNEL_ACCESS_TOKEN` に公式アカウント（Messaging API チャネル）の長期トークンを設定する
3. 公式アカウントを各店舗のLINEグループに招待し、グループIDを「管理」画面の店舗の「LINEグループID」に入力する

トークンかグループIDが未設定の店舗には通知されません（アプリの操作は通常どおりできます）。

- 写真の保管期間（完了日から1年）経過後の自動削除。案件の記録（日付・費用）は残す前提で `repairs.photos_purged_at` を用意済み
- 全50店舗の建物データ（資料受領後、管理画面の「建物」から各店舗の階数・部屋数・部屋タイプ・共用部を設定）
- 既存の「重点清掃箇所」メモは、3Dモデルの部屋パネルに残してあります
